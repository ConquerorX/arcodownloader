# Архитектура

Расширение намеренно состоит из трёх небольших слоёв. Каждый слой выполняет одну задачу и не расширяет полномочия остальных.

```
┌─────────────────────────────────────────────────────────────────────┐
│  player.arcod.xyz                                                   │
│                                                                     │
│  ┌───────────────────────┐        ┌──────────────────────────────┐  │
│  │ arcod-grab.js         │        │ relay.js                     │  │
│  │ MAIN world            │◄──────►│ ISOLATED world               │  │
│  │                       │postMsg │                              │  │
│  │ • панель + CSS        │        │ • двусторонний мост          │  │
│  │ • fetch + чтение FLAC │        │ • доступ к chrome.runtime    │  │
│  │ • очередь + шаблон    │        │                              │  │
│  └───────────────────────┘        └───────────────┬──────────────┘  │
└───────────────────────────────────────────────────┼─────────────────┘
                                                    │ sendMessage
                                    ┌───────────────▼──────────────┐
                                    │ background.js                │
                                    │ MV3 service worker           │
                                    │ • downloads API              │
                                    │ • значок (ON / длина очереди)│
                                    │ • жизненный цикл вкладок     │
                                    └───────────────┬──────────────┘
                                                    │
                                          менеджер загрузок браузера
```

## Слои

### 1. `arcod-grab.js` — MAIN world

Работает в собственном JavaScript-контексте страницы. Причина одна: **запрос должен исходить из origin страницы.** ARCOD отклоняет клиентов вне браузера (curl, PowerShell, Node) ответом 502; поэтому вызов `fetch` должен выглядеть как обычный запрос страницы, а не как запрос, принудительно отправленный через CDP.

Задачи:

- Построить панель внутри теневого DOM (`attachShadow`) — CSS страницы не влияет на панель, а CSS панели не влияет на страницу.
- Вызывать конечные точки `/api/player/get-album` и `/api/player/stream/{id}`.
- Прочитать первые ~64 КБ потока и разобрать заголовок FLAC (`readFlacHead`).
- Хранить качество, шаблон имени файла и очередь в `localStorage` (origin ARCOD).
- Либо потоково писать загрузку прямо на диск (`showSaveFilePicker`), либо передавать её в `background.js`.

### 1b. `media-hook.js` — MAIN world, document_start

Пассивно запоминает аудиоэлементы, которые создаёт сайт (включая `new Audio`), и выход Web Audio (главный `GainNode`); для `arcod-grab.js` он открыт только через узкое рукопожатие `CustomEvent` для чтения/установки громкости. Он не выполняет никаких автоматических действий, даже когда панель закрыта.

### 2. `relay.js` — ISOLATED world

MAIN world не имеет доступа к API `chrome.*`, а service worker не может напрямую писать в страницу. `relay.js` — **единственный и узкий канал** между этими сторонами:

```js
// страница  →  расширение
window.postMessage({ __arcodgrab: true, type: 'request', id, req, args })
// расширение  →  страница
window.postMessage({ __arcodgrab: true, type: 'response', id, ok, res })
```

Пересылаются только типы сообщений `arcodgrab:*` из белого списка; ни один скрипт на странице не может выполнить произвольный вызов `chrome.*`. При нажатии кнопки на панели инструментов `arcodgrab:toggle` тоже спускается по этому же каналу.

### 3. `background.js` — service worker

- Выполняет вызовы `chrome.downloads.download` / `open` / `show` / `showDefaultFolder`.
- Принимает только адреса `https://player.arcod.xyz/`.
- Управляет значком вкладки: **ON**, пока панель открыта, а при наличии заданий в очереди — число.
- Сглаживает различия API `downloads` в Chrome (callback) и Firefox (Promise) единой обёрткой `callApi`.

## Протокол сообщений

| Тип | Направление | Назначение |
|---|---|---|
| `arcodgrab:toggle` | background → страница | Показать/скрыть панель |
| `arcodgrab:panel-ready` | страница → background | Установить значок `ON` |
| `arcodgrab:queue-count` | страница → background | Вывести длину очереди на значок (при `0` — `ON`) |
| `arcodgrab:download` | страница → background | Передать адрес потока менеджеру загрузок |
| `arcodgrab:open` | страница → background | Открыть скачанный файл в операционной системе |
| `arcodgrab:show` | страница → background | Показать загрузку в списке |
| `arcodgrab:show-folder` | страница → background | Открыть папку загрузок |
| `arcodgrab:commands` | страница → background | Перечисляет назначенные клавиши `commands` |
| `arcodgrab:open-shortcuts` | страница → background | Открывает вкладку настроек горячих клавиш браузера |
| `arcodgrab:command` | background → страница | Передаёт странице назначенную команду (`prev`, `next`, `volUp`, `volDown`) |

## Процесс загрузки

```text
ticket()            →  /api/player/stream/{id}?quality={q}
                       ↓  { url, quality }
fetch(ticket.url)   →  поток (ReadableStream)
                       ↓
  saveMode = 'fsa'  →  showSaveFilePicker → writable.write(chunk) …
  saveMode = 'dl'   →  chrome.downloads.download({ url, filename })
```

В режиме `dl` поток вообще не буферизуется в памяти: адрес сразу уходит менеджеру загрузок браузера, и файл записывает браузер. В режиме `fsa` фрагменты потоково записываются на диск; поскольку полный путь к файлу недоступен для JS, функция «показать в папке» открывает папку загрузок браузера.

## Модель качества

Таблица качества ARCOD задаёт **потолок**:

| Канал | Бит | кГц |
|---|---|---|
| `5` | 16 | 44.1 |
| `6` | 16 | 48 |
| `7` | 24 | 96 |
| `27` | 24 | 192 |

Сервер пересекает запрошенный потолок с собственным разрешением записи. Поэтому запрос 24/192 — это не повышение, а «лучшее из возможного». Панель делает эту разницу видимой, показывая перед загрузкой **реальные** значения, прочитанные из потока.

## Проверка

`readFlacHead(u8)` ищет в первых байтах:

1. магическую сигнатуру `fLaC`,
2. цепочку блоков метаданных (`STREAMINFO`, `PADDING`, `SEEKTABLE`, `VORBIS_COMMENT`, `PICTURE`…),
3. из тела STREAMINFO — частоту дискретизации, число каналов, разрядность, общее число сэмплов и MD5.

Результат сообщается как одно из трёх состояний: **оригинал**, **перепаковано** (MD5 нулевой), **теги удалены** (нет VORBIS_COMMENT).

## Дизайн

Панель следует языку Apple HIG: семантические цветовые токены (автоматически светлая/тёмная), материальные поверхности `backdrop-filter`, разделители 0,5 px, сетка 8 pt. Простой режим включается сам при первом запуске с `prefers-contrast: more`.

## Горячие клавиши и ввод

- **Поток горячих клавиш:** `commands` в манифесте (`arcod-prev`, `arcod-next`, `arcod-vol-up`, `arcod-vol-down`) не имеют клавиш по умолчанию; их назначают на `chrome://extensions/shortcuts`. `background.js` получает `onCommand` и выбирает целевую вкладку в таком порядке: с играющим звуком, активная, использованная последней. Если вкладки ARCOD нет, он молчит. Команда идёт через `relay.js` как `arcodgrab:command` (белый список: `prev`, `next`, `volUp`, `volDown`) и попадает в MAIN world сообщением `type: 'command'`, которое обрабатывает `scCommand`. Новых разрешений не требуется.
- **Область действия:** `cfg.scScope` равен `'page'` (по умолчанию) или `'global'`. В глобальной области работают только клавиши `commands`; назначенные в панели собственные клавиши действуют только на странице.
- **Изоляция клавиатуры:** при вводе в панели клавиши (включая Space) не попадают на страницу; горячие клавиши страницы не срабатывают во время ввода в панели.
- **Контекстное меню** работает и при закрытой панели; само по себе оно ничего не делает, панель не создаёт, а состояние показывает тостом. Добавление в очередь проходит через единственный путь `queueAdd()`.
- **Шаблон имени файла** редактируется блочным редактором (чипы) с перетаскиванием; `cfg.template` остаётся строкой, её преобразуют `tplParse`/`tplBuild`. Способ сохранения — `cfg.saveMode`: `'dl'` | `'fsa'` | `'auto'`; очередь всегда загружается средствами браузера.
- **Громкость:** сначала пробуется ползунок громкости сайта, затем `audio.volume`.

## Языки

Все видимые пользователю тексты хранятся в единственном словаре `I18N` в `arcod-grab.js` (`tr`, `en`, `de`, `fr`, `es`, `ru`). `t('ключ', { n })` читает его; отсутствующий ключ сначала берётся из турецкого, а если и там его нет — используется сам ключ. Статические узлы помечаются атрибутами `data-i18n*`; при смене языка `applyI18n()` перезаписывает их все без перезагрузки страницы. `background.js` возвращает стабильный `code` вместо текста ошибки; перевод выполняется в панели. `T()` делает первую букву заглавной с учётом языка. Шаги добавления языка: [README → Языки](../../README.ru.md#-языки).

## Почему один файл?

`arcod-grab.js` хранит панель, CSS и движок загрузки в одной IIFE. У скриптов, внедряемых в MAIN world, нет загрузки модулей, а каждый дополнительный файл — это лишний запрос на каждой странице. Поэтому это осознанный выбор: **один скрипт, ноль зависимостей, ноль сборки.** `arcod-grab.js` по-прежнему единственный основной скрипт; `media-hook.js` вынесен отдельно лишь потому, что должен загружаться раньше скриптов страницы.
